# Internationalisation (fr / ar)

## Two locales, carried in the URL
The supported locales are `config('app.supported_locales')` (`fr`, `ar`), `config('app.rtl_locales')` lists the right-to-left ones (`ar`). Every page lives under `/{locale}` (see the routes rule); `SetLocale` resolves it (URL → account language → 12-month cookie → session → browser → `app.locale` = fr) and shares `locale`, `locales`, `direction` with every Inertia page. Never read the locale from the document or a cookie in a component: use `useLocale()` (`locale`, `direction`, `alternateLocales`).

## Frontend texts: vue-i18n only
- Every interface text goes through `const { t } = useI18n()` (or `$t` / `<i18n-t>` in templates). No hardcoded French or Arabic in components, layouts or page options (`defineOptions({ layout: { title: 'auth.login.title' } })` takes keys).
- Keys live in `resources/js/i18n/locales/fr.json` (the master schema) and `ar.json`, grouped by area (`common`, `public`, `auth`, `settings`…). Both files must define exactly the same keys, and every key must be used: `npm run check` runs `check-keys.ts` and fails otherwise. Remove a key when its last use goes.
- vue-i18n message syntax: `{name}` is a placeholder, `@` starts a linked message and `|` separates plural forms. Write a literal `@` or `|` as `{'@'}` / `{'|'}` (e.g. `"vous{'@'}exemple.dz"`): a bare one breaks the compilation of the message and blanks the component that renders it.
- Sentences containing a link use `<i18n-t keypath="…">` with named slots, not concatenated fragments.
- Language links are plain `<a href>` (full page load, `useLocale().alternateLocales`); see `components/public/LanguageToggle.vue`.

## Backend texts: lang/{fr,ar}
Validation, SRS screen messages, e-mails and notifications use `lang/fr/*.php` and `lang/ar/*.php` (plus dev's `lang/{fr,ar}.json` for package strings). Every key must exist in BOTH languages: `app.fallback_locale` is `en`, which has no translations, so a key missing in Arabic shows as a raw key (and `__('module.attributes')` returns a string instead of an array). SRS-mandated texts get their own module key (e.g. `accounts.sign_in.invalid_credentials`) rather than overriding Laravel's (`auth.failed`). Arabic texts are drafts until the client supplies the approved ones; mark new Arabic files as such.

## Right-to-left layout
- reka-ui gets the direction from the `ConfigProvider` set up in `app.ts`; `<html dir>` comes from the shared `direction`.
- Use logical utilities only: `ms-*/me-*`, `ps-*/pe-*`, `start-*/end-*`, `text-start/end`, `rounded-s/e`, `border-s/e`. Never `ml/mr/pl/pr/left/right/text-left/text-right` (they do not flip). Directional icons (arrows, chevrons pointing sideways) get `rtl:rotate-180`. A sheet/drawer opens from the end side (`direction === 'rtl' ? 'left' : 'right'`).
- Inputs whose content is always left-to-right (the 6-digit code, e-mail addresses in mono contexts) set `dir="ltr"`.
- No letter-spacing on Arabic: anything with `tracking-*` also gets `rtl:tracking-normal` (spacing breaks the cursive joining).
- Fonts switch with the page language through `--ess-font-sans` (`resources/css/app.css`): Poppins for French, IBM Plex Sans Arabic for Arabic. Use `font-sans`; never set a font family by hand.
